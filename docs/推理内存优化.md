# 推理内存优化

> Qwen2.5-7B Q4_K_M GGUF 的内存预算与进一步压缩方案。按平台选配置。

## 当前默认：Q4_K_M + KV Cache q8_0

启动命令：

```bash
llama-server -m model.gguf --ctx-size 2048 \
  --cache-type-k q8_0 --cache-type-v q8_0
```

### Qwen2.5-7B 内存预算（单序列，2048 ctx）

| 组件 | FP16 KV | q8_0 KV | q4_0 KV |
|------|:---:|:---:|:---:|
| 权重 Q4_K_M | 4.7 GB | 4.7 GB | 4.7 GB |
| KV cache | 115 MB | **57 MB** | **28 MB** |
| 运行时开销 | ~0.5 GB | ~0.5 GB | ~0.5 GB |
| **合计** | **~5.3 GB** | **~5.3 GB** | **~5.2 GB** |

> KV cache 绝对值不大（2048 ctx 下仅 115MB），但长对话/多并发时成倍放大。q8_0 几乎零质量损失。

## 三档方案

### 默认（推荐）：Q4_K_M + q8_0 KV

```bash
llama-server -m model_Q4_K_M.gguf --ctx-size 2048 \
  --cache-type-k q8_0 --cache-type-v q8_0
```

- 内存 ~5.3 GB
- 1080Ti 11G ✓ 本地 8G ✓（需关桌面）
- 质量无损

### 激进：Q3_K_M + q4_0 KV

```bash
# 需先重新量化 GGUF：
./llama-quantize f16.gguf model_Q3_K_M.gguf Q3_K_M

# 启动：
llama-server -m model_Q3_K_M.gguf --ctx-size 2048 \
  --cache-type-k q4_0 --cache-type-v q4_0
```

- 内存 ~3.8 GB（省 1.5GB）
- 本地 8G 充裕，手机 6G 可冲
- 轻微质量损失，回复短（max_tokens=128）时几乎无感

### 极限：IQ3_XXS + q4_0 KV

```bash
./llama-quantize f16.gguf model_IQ3_XXS.gguf IQ3_XXS

llama-server -m model_IQ3_XXS.gguf --ctx-size 2048 \
  --cache-type-k q4_0 --cache-type-v q4_0
```

- 内存 ~3.5 GB（省 1.8GB）
- 手机 6G 推荐
- 质量有感知下降，但在短回复 + 风格迁移场景（v5 attention-only 思路）影响可控

## 权重量化对比

| 量化 | 大小 | vs Q4_K_M | 推荐场景 |
|------|------|:---:|------|
| Q4_K_M | ~4.7 GB | 基准 | 1080Ti / 本地 8G（临界） |
| Q5_K_M | ~5.7 GB | +1.0 GB | 不推荐（更大） |
| Q3_K_M | ~3.5 GB | -1.2 GB | 本地 8G 充裕 |
| IQ3_XXS | ~3.2 GB | -1.5 GB | 手机 6G |
| Q2_K | ~2.9 GB | -1.8 GB | 极限压缩 |
| IQ2_XXS | ~2.7 GB | -2.0 GB | 仅实验 |

## Flash Attention

需 CUDA 编译 llama.cpp（当前 CPU 模式不适用）：

```bash
# 编译时加 CUDA（需 CUDA 12.x，AutoDL 4090D 默认 11.8 不行）
cmake -B build -DGGML_CUDA=ON llama.cpp
cmake --build build -j

# 启动时加 -fa
llama-server -m model.gguf --n-gpu-layers 99 -fa \
  --cache-type-k q8_0 --cache-type-v q8_0
```

- 省 200-500MB（注意力矩阵不物化）
- 同时加速推理
- **前提**：换 CUDA 12 实例 / 或本地有 CUDA 12 的 GPU

## 各平台推荐

| 平台 | 权重 | KV | 内存 | 备注 |
|------|------|-----|:---:|------|
| AutoDL 4090D (24G) | Q4_K_M | q8_0 | ~5.3G | 当前默认，余量充裕 |
| 1080Ti (11G) | Q4_K_M | q8_0 | ~5.3G | 单并发 OK |
| 本地 i7/8G (CPU) | Q3_K_M | q4_0 | ~3.8G | 关闭浏览器等重应用 |
| 手机 6G | IQ3_XXS | q4_0 | ~3.5G | ChatterUI/PocketPal |
| 手机 4G | IQ2_XXS | q4_0 | ~3.0G | 极限，可试 |

## 注意事项

- **K/V 类型要对称**：`-ctk q8_0 -ctv q8_0` 不要混搭（如 `q8_0` + `q4_0`），否则脱离 Flash Attention 快速路径，反而变慢
- **不切 TurboQuant fork**：主分支 `q8_0` 对短回复场景（max_tokens=128）已足够，fork 维护成本高于收益
- **Qwen2.5-7B 是 GQA**（4 KV heads），KV cache 本身已比 MHA 小 4×，量化收益不如非 GQA 模型显著，但 q8_0 零成本无脑加
- **重新量化无需校准数据**：Q4_K_M → Q3_K_M / IQ3_XXS 直接用 `llama-quantize` 从 f16 GGUF 转，不需要校准数据集
